# 基座首轮加固计划（2026-10-26）

范围：保留当前 Cursor 工作区，先完成公开图片代理与分类 URL 的两项上线前修复；不触碰会员下载和静态营销内容迁移。

1. 为 Directus 本地图片代理写失败验证：任意 UUID 不应直接取到文件；页面生成的图片 URL 应带服务端签名，篡改 ID 或查询参数应拒绝。改 `web/src/lib/media.ts` 与 `web/src/app/api/cms-asset/[fileId]/route.ts`，并补 `.env.example` 说明。通过脚本、TypeScript 和构建验证。
2. 为分类跨语言 slug 写 HTTP 状态验证：错误语言的分类地址返回真实 3xx 和目标语言的 canonical 地址。改 `web/src/middleware.ts`，仅针对分类详情向 Directus 查询必要翻译字段；页面现有兜底跳转保留。验证中文、英文与正常分类访问。
3. 修复本轮发现的验收脚本导入错误；后台个人预设冲突先确认成因，不删除用户偏好。运行与本轮相关的门禁及 `git diff --check`，更新项目进度记录。
4. 把首页 Banner 作为第一个完整 CMS 联动样本：先验证中英文同条记录、各语言发布状态、共用图及语言覆盖图、站内与外部链接的映射；再让首页服务端取 `home_banner` 并把数据交给现有轮播组件。用种子数据与页面 HTTP 结果验证，无后台数据时不显示虚构轮播。

风险：通用图片代理的签名保护的是公开页面生成的图片链接；会员私有文件仍需独立认证与授权下载接口，不能复用本接口。

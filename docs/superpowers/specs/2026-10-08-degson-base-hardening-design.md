# DEGSON 官网基座加固设计

日期：2026-10-08

## 1. 目标与边界

本次工作只优化 `D:\degson-pilot` 当前 demo 的工程基座，不实现 PRD 中尚未开始的业务模块。目标是让现有 demo 在继续扩展前具备稳定的 URL 契约、数据约束、内容安全、媒体抽象、发布缓存边界和可复现文档。

本次明确不实现：会员体系、完整产品详情页、Meilisearch、下载权限、询盘系统、全量迁移、生产域名切换、CI/CD、灰度和灾备演练。

## 2. 已确认的生产 URL 方案

- 英文主站使用无语言前缀的路径，例如 `/`、`/product/category/...`。
- 其他国际语言使用路径前缀，例如 `/de/...`、`/es/...`。
- 中文使用独立域名 `degson.com.cn`，不在国际主域生成可索引的 `/zh/...` 页面。
- 开发环境允许通过环境配置使用当前 demo 的 `/en`、`/zh` 形式，以保持本地演示可运行；生产 URL 规则不再依赖硬编码。
- canonical、hreflang、语言切换器和未来 sitemap 都必须来自同一套语言站点配置。

## 3. 改造单元

### 3.1 站点与语言配置

把语言、域名、默认语言、路径前缀和中文独立域名抽成配置边界。页面只调用统一 URL 函数，不直接拼接 `/en`、`/zh` 或固定域名。

### 3.2 数据模型约束

修正 schema 建模脚本和 snapshot，使业务约束不只存在于备注中：

- `series.matecode` 建立唯一性和查询索引。
- `product.order_no` 建立唯一性和查询索引。
- 翻译实体的语言行建立唯一约束，防止同一实体重复同语言记录。
- slug 的唯一范围与最终 URL 规则保持一致，并在导入/发布前验证。
- 为状态、父级关系、系列归属和翻译字段保留查询索引。
- 建模脚本不再调用已知会导致 Directus 11 崩溃的关系 PATCH 路径；关系变更必须使用可重建流程。

由于当前种子数据存在历史重复裁决问题，唯一约束落地前要先由验证脚本报告冲突，不能静默截断或覆盖数据。

### 3.3 内容与翻译边界

补齐 `site_settings` 的翻译边界，并将首页中的运营文案从 TSX 常量中移出到受控数据结构。保留现有翻译适配层，不让页面直接感知 Directus 翻译表。

产品参数本次只定义扩展接口和数据约束，不实现完整产品页：固定业务字段继续留在产品主表，后续可扩展到参数定义、参数值、单位、数据类型和筛选标记。

### 3.4 内容安全与媒体边界

- 富文本进入前台前必须经过白名单净化。
- 禁止脚本、事件属性、`javascript:` URL、未经批准的 iframe 和未知外链媒体。
- 媒体 URL 通过统一 resolver 生成，不让页面散落环境相关的 Directus/OSS 地址。
- 公开媒体和未来受限媒体保留不同访问边界。
- 前台继续使用字段白名单和只读 token；不向页面返回草稿、内部备注、审计字段和管理字段。

### 3.5 发布与缓存接口

保留当前 ISR 作为 demo 默认策略，但把缓存 tag/path 的命名和刷新入口抽成稳定接口。为后续 Directus webhook 预留事件 ID、幂等、重试和失败记录的数据结构，不在本次实现队列或搜索同步。

### 3.6 文档与验证

生成新的基座 PRD，明确：

- 当前已经验证的能力和证据；
- 本阶段不做的功能；
- URL、模型、权限、媒体和发布契约；
- 基座验收脚本；
- 后续 M1.5/M2/M3 的进入条件。

同时修正旧 README 与交接文档中 Directus 11/12、M0.2/M1、URL 方案互相冲突的描述。

## 4. 数据流

```text
Directus 内容/翻译/媒体
        ↓ 只读字段白名单
repository 适配层
        ↓ 已解析的语言视图
Next 页面与 metadata
        ↓ 统一 URL / media resolver
HTML、JSON-LD、canonical、hreflang
```

后续发布链路预留为：

```text
Directus 发布 → 签名事件 → 缓存失效 → 搜索同步 → 结果记录/补偿
```

## 5. 错误处理与兼容策略

- 未配置生产域名时，开发环境继续使用本地 demo URL。
- 不支持的语言回退到默认语言，但不会生成错误 hreflang。
- 发现唯一性冲突时，建模/验证脚本失败并输出冲突记录，不覆盖已有数据。
- 富文本净化失败时阻止发布或返回明确错误，不静默展示原始 HTML。
- 媒体 URL 缺失或不在允许来源时使用安全占位，不拼接不可控来源。
- 旧 demo 路径不会被无声删除；生产迁移阶段另行通过 URL 总账和 301 处理。

## 6. 验证策略

先增加能证明约束的验证，再实现对应变更：

1. URL 解析测试：英文主域、国际语言前缀、中文独立域名和本地 demo 模式。
2. 数据模型检查：唯一约束、索引、重复语言行和重复 slug 报告。
3. 内容安全测试：危险 HTML、危险 URL、允许标签和正常富文本。
4. 前台回归：现有 `verify_m1_web.mjs` 继续保持通过，增加 metadata/canonical/hreflang 断言。
5. TypeScript 检查和生产构建检查。
6. 文档一致性检查：仓库中不再把 Directus 12 或旧 `/en` 方案描述成当前生产方案。

## 7. 完成标准

- 当前 demo 页面继续可运行，现有 M1 业务链路不回归。
- schema snapshot、建模脚本和验证脚本表达同一套约束。
- 生产 URL 方案在代码配置、metadata、语言切换和文档中一致。
- 富文本不再直接以未净化 HTML 输出。
- 新 PRD 能单独作为后续开发基线，不把本次未实现的业务功能误标为已完成。
- 所有变更可在隔离分支中审阅，并提供验证结果和已知限制。

# DEGSON 新官网基座优化版 PRD

版本：2026-10-08
适用项目：`D:\degson-pilot`
文档定位：当前 demo 基座的加固基线，不是完整官网业务 PRD。

## 1. 文档目标

本版本只定义当前 demo 在继续扩展前必须稳定的工程基座。它承接 `新官网prd_2026-09-30_v4.md` 的目标，但主动把会员、搜索、下载、询盘、全量迁移和生产切换排除出本次实现范围。

核心原则：

> 技术路线可行，不等于生产就绪。基座先保证 URL、数据身份、安全边界、缓存接口和可重建性，再进入业务页型开发。

## 3. URL 与语言契约

### 3.1 生产站

```text
英文主站： https://www.degson.com/
德语站：   https://www.degson.com/de/
西语站：   https://www.degson.com/es/
中文站：   https://www.degson.com.cn/
```

英文是默认语言，不使用 `/en`。其他国际语言使用路径前缀。中文使用独立域名，不在国际主域生成可索引 `/zh/` 页面。

### 3.2 本地 demo

本地通过 `SITE_MODE=demo-path` 保留：

```text
http://localhost:3000/en/
http://localhost:3000/zh/
```

本地模式只是开发兼容形态，不得直接复制为生产 URL 规则。

### 3.3 URL 输出要求

canonical、hreflang、语言切换器、JSON-LD URL 和未来 sitemap 必须使用同一套站点策略。禁止根据 IP、UA、浏览器语言或 `Accept-Language` 强制跳转。

## 4. 数据模型基线

### 4.1 已有核心实体

```text
category + category_translations
series + series_translations
product + product_translations
news + news_translations
site_settings
languages
```

### 4.2 必须成立的身份约束

- `series.matecode` 全局唯一。
- `product.order_no` 全局唯一。
- 同一父实体同一语言最多一条翻译行。
- 同一翻译集合中 `(language, slug)` 不得重复。
- 分类、系列、产品、翻译、媒体和下载之间必须保持引用完整性。

约束执行顺序：

```text
重复检查 → 业务裁决 → 约束 SQL → schema snapshot → 迁移/导入
```

不得在导入时静默覆盖重复值。

### 4.3 下一步模型迁移

以下模型进入下一次基座迁移，不在本次 demo 加固中假装完成：

- `site_settings_translations`
- `parameter_definition`
- `product_parameter`
- `media` / `download`
- `redirect`
- `page` / `page_translations`

这些模型必须先完成字段字典、权限、snapshot、重建和验证脚本，再被前台页面消费。

## 5. 内容安全与媒体规则

- CMS 富文本只能输出语义 HTML。
- 允许的基础标签包括段落、标题、列表、表格、链接和图片。
- 删除脚本、事件属性、`javascript:` URL、危险 CSS、未知 iframe 和追踪像素。
- 图片和附件必须通过媒体库或受控 resolver 进入页面。
- 媒体来源必须在允许域名列表内。
- 公开媒体和未来受限媒体使用不同访问策略。
- 受限下载不得依赖前端隐藏 URL，必须由服务端鉴权。
- 运营不能写入 SQL、PHP、模板代码或任意 JavaScript。

## 6. API、权限与缓存

### 6.1 前台 API

- 前台不直连数据库。
- 前台只使用只读服务账号/token。
- 每个公开集合使用显式 `fields` 白名单。
- 草稿、内部备注、审计字段、导入字段和管理字段不得返回。
- 发布状态、语言可用性和权限条件必须同时满足。

### 6.2 缓存 tag

当前稳定 tag：

```text
content:site-settings
content:category
content:series
content:product
content:news
content:media
```

后续发布链路：

```text
Directus 发布
→ 签名 webhook
→ 事件 ID / 防重放 / 幂等
→ Next.js tag/path revalidate
→ 搜索增量同步
→ 结果、重试、DLQ 和人工补偿
```

本阶段只建立 tag 契约，不实现 webhook 队列和搜索同步。

## 10. 生产 Gate

本 PRD 不替代生产 Gate。全量迁移或主域切换前仍必须完成：

- HG-1：迁移源权威、旧功能裁决、URL 总账。
- HG-2：双跑、灰度、delta replay、回滚演练。
- HG-3：MySQL、schema、媒体、索引和密钥恢复演练。
- CL-A：身份与会员。
- CL-B：隐私与合规。
- CL-C：API、发布、下载和补偿。
- CL-D：容量、性能、告警和降级。

## 11. 与原 PRD v4 的关系

原 PRD v4 继续作为完整官网目标和生产治理参考。本文件只负责当前 demo 基座加固，优先级更高的冲突以本文件的 URL、数据和安全契约为准。原 PRD 中尚未实现的会员、搜索、全量迁移、生产切换和灾备内容，不得因为 demo 验证通过而标记为完成。

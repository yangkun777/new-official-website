# M0.3 底座重建手册

> **唯一验收标准**：把 `degson_pilot` 整个删掉，只靠本仓库把它一模一样地重建出来。
> **本手册已实测通过**（2026-09-23）：重建库与主库的 `directus_fields` = 96/96、`directus_collections` = 10/10、`directus_relations` = 7/7，10 张业务表列数逐表一致。

## 0. 前置：两个必须知道的坑（本机实测）

### 坑 1：Node 22 目录里的 pnpm 是 DLP 密文

```
C:\nvm\v22.23.2\node_modules\pnpm\bin\pnpm.cjs   前 8 字节: 88 7D 1C 46 ...
                                                 ↑ 天锐绿盾密文，Node 读出来是乱码 → SyntaxError
```

**原因**：`.cjs` 当年在加密名单里。**解法是 PATH 顺序——全局 npm 目录必须排在 Node 22 目录前面**：

```powershell
# ✅ 正确（pnpm 走全局的 12.5.1，node 走 22.23.2）
$env:PATH = "C:\Users\admin\AppData\Roaming\npm;C:\nvm\v22.23.2;" + $env:PATH

# ❌ 错误（会命中 v22 目录里那个加密的 pnpm）
$env:PATH = "C:\nvm\v22.23.2;" + $env:PATH
```

### 坑 2：pnpm 12 的构建设置搬到了 `pnpm-workspace.yaml`

`package.json` 里的 `"pnpm": { "onlyBuiltDependencies": [...] }` **已被 pnpm 12 忽略**，会报 `ERR_PNPM_IGNORED_BUILDS`。现行写法在 `cms/pnpm-workspace.yaml`：

```yaml
allowBuilds:
  argon2: true        # Directus 密码哈希（必需）
  esbuild: true       # 构建工具链
  isolated-vm: true   # Directus Flows 沙箱（Node 22 有预编译二进制）
  sharp: true         # 图片处理（必需）
  oracledb: false     # 不用 Oracle
  sqlite3: false      # 不用 SQLite
  braintrust: false   # AI 评测库，运行时不需要
```

> **为什么用 Node 22 而不是 24**：`isolated-vm` 在 Node 24（ABI 137）没有预编译二进制，本机又没有 C++ 工具链。Node 22（ABI 127）有 prebuilt，装完即用。**这是"版本锁定"的一部分，不要随意升级 Node。**

### 坑 3：环境变量无法覆盖 `.env`

`$env:DB_DATABASE=xxx` 对 Directus CLI **不生效**（它的 dotenv 覆盖了进程环境变量）。要指向别的库**必须临时改 `.env`**（并保证还原）。

### 坑 4：端口 8055 被旧进程占用时，验证会打到旧服务上

启动前先确认端口空闲，否则 `ping`/`login` 成功也可能是旧服务在应答。

## 2. 从零重建（完整步骤）

### 2.1 起 MySQL（端口 3307）

```powershell
D:\degson-pilot\mysql\bin\mysqld.exe --defaults-file="D:\degson-pilot\mysql\my.ini"
# 等待 3307 开始监听
```

### 2.2 建两个库（collation 必须显式指定）

```sql
CREATE DATABASE degson_pilot  CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_ai_ci;
CREATE DATABASE degson_legacy CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_ai_ci;
```

> **为什么必须显式写 `COLLATE`**：若只写 `DEFAULT CHARSET=utf8mb4`，MySQL 8 会落到 charset 默认 collation `utf8mb4_0900_ai_ci`，与库里其他表不一致（M0.2 的三种 collation 混用就是这么来的）。

### 2.3 导入旧库底料

```powershell
mysql -h127.0.0.1 -P3307 -uroot -pdegson_dev_2026 degson_legacy < data\01_legacy_subset.sql
```

> ⚠️ 旧库表的字符集是 `utf8mb3 / utf8_general_ci`。**不要试图 CONVERT 成 utf8mb4**——`hr_article` 的复合索引 `(matecode, catid, text1, text2, text3, status)` 会超 3072 字节上限报 `ERROR 1071`。MySQL 8 在跨库比较时会自动转换，不影响使用。

### 2.4 装依赖

```powershell
$env:PATH = "C:\Users\admin\AppData\Roaming\npm;C:\nvm\v22.23.2;" + $env:PATH
cd D:\degson-pilot\cms
pnpm install
```

### 2.5 配置 `cms/.env`

```
PORT=8055
PUBLIC_URL=http://localhost:8055
SECRET=<强随机>
KEY=<强随机>
DB_CLIENT=mysql
DB_HOST=127.0.0.1
DB_PORT=3307
DB_USER=root
DB_PASSWORD=<密码>
DB_DATABASE=degson_pilot
ADMIN_EMAIL=admin@degson.dev
ADMIN_PASSWORD=<密码>
WEBSOCKETS=false
RATE_LIMITER_ENABLED=false
```

### 2.6 bootstrap + 应用快照

```powershell
cd D:\degson-pilot\cms
.\node_modules\.bin\directus.CMD bootstrap
.\node_modules\.bin\directus.CMD schema apply --yes .\snapshot.yaml
```

**到这一步，后台模型就完整回来了**（10 个集合 / 96 个字段 / 7 个关系）。

### 2.7 启动并验证

```powershell
.\node_modules\.bin\directus.CMD start
# 另开窗口
curl http://localhost:8055/server/ping      # 期望 pong
```

### 2.8 灌业务数据

```powershell
mysql -h127.0.0.1 -P3307 -uroot -pdegson_dev_2026 < data\03_seed.sql
```

## 3. 模型变更流程（**必须遵守**）

快照是**唯一**的模型真相来源。任何结构变更按此流程：

```
1. 在 Directus 界面（或 data/build_model.mjs）改模型
2. 导出快照：cd cms && .\node_modules\.bin\directus.CMD schema snapshot --yes .\snapshot.yaml
3. 检查 diff：git diff cms/snapshot.yaml     ← 这一步是 review 的关键
4. 提交
```

> **禁止**只改界面不导快照——那正是 M0.2 的状态：界面点出来的模型，仓库里没有任何记录，无法重建。

**恢复快照到某个历史版本**：`git checkout <commit> -- cms/snapshot.yaml` 然后 `schema apply`。

## 4. 当前模型（M0.3 基线）

```
category                8 字段   ← 名称/slug 在 category_translations（语言无关字段在主表）
series                  8 字段   matecode = 系列码
product                10 字段   order_no = 订货号；title = 型号
news                    7 字段
site_settings           9 字段   单例
languages               6 字段   语言单一来源（en / zh）

category_translations  12 字段 ┐
series_translations    12 字段 │ 四个翻译表用【同一套字段模板】：
product_translations   12 字段 │ language / name / slug / seo_title /
news_translations      12 字段 ┘ seo_description / h1 / short_description / description
```

**翻译表统一模板的目的**：运营心智只有一套；M1 往上加实体时不会长出不兼容的形状。

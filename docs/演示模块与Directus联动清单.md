# 演示模块与 Directus 联动清单

> **用途**：让后续接手的开发者或模型一眼区分“为了演示暂时写在前端的内容”和“当前已从 Directus 读取的数据”，避免把演示完成误判为正式内容管理完成。
>
> **当前阶段**：领导演示版。界面与交互用于确认方向，部分营销内容使用前端静态双语数据；已有产品、型号等业务数据仍按实际来源读取。
>
> **最后更新**：2026-10-26

## 必须遵守的项目结论

**这批页面是演示项目。演示通过并进入正式开发后，前台每个内容模块都必须能通过 Directus 管理和配置。** 当前写死的文案、卡片、图片、视频、FAQ、导航项、展示顺序及区块组合只为演示服务，不能当作正式内容，也不能标记为“已完成 Directus 联动”。

正式开发时，所有可见页面区块均须纳入 Directus 内容模型，包括首页、产品展示、行业解决方案、关于、服务、FAQ、新闻、全站导航和页脚。中英文内容、媒体、排序、发布状态、按钮及目标链接、区块组合等运营内容由 Directus 管理。前端负责模板、样式、交互和动效实现；确实需要运营调整的交互参数应进入 Directus 配置。每个模块均须验收真实路径：**后台编辑并保存 → 前台对应语言及页面显示更新**。

新增或改造静态演示模块时，必须在本文件登记模块、当前数据来源、哪些部分是静态演示、正式开发迁入 Directus 的内容，以及相关代码入口。状态发生变化时同步更新本文和 [`AI-项目总况.md`](./AI-项目总况.md) §5.2。

## 演示稿与正式版的边界

- 当前静态双语文案、演示数据、图片选择、卡片和区块编排的用途是让领导评审页面内容、排版与动效；它们不是长期数据源。
- 当前产品目录中的真实系列、订货号、参数、认证条件和下载文件仍来自 Directus；营销包装为静态不代表产品事实数据也被 mock。
- 后台已有集合、字段或编辑界面，不等于对应前台模块已经接入。必须看到前台读取该数据并完成“后台修改 → 前台显示”验证，才能改为已联动。
- 动画、响应式布局和交互代码通常由前端维护；动画涉及的图片/文案/排序，以及需要运营调节的开关、轮播间隔等参数，正式开发时由 Directus 提供。
- Directus 建模须遵守根目录 `AGENTS.md`：中英翻译、中文字段说明、媒体关系与预览；固定选项使用中文标签的下拉或对应控件，并同步维护应用脚本、校验脚本、种子、权限和验收路径。
